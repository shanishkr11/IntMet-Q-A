Level 1 — Foundational C# & .NET Basics
Core language features every .NET developer must master
9 Questions
Basic Syntax
Q1 What is the difference between value types and reference types in C#?
✔ Answer

Value types store data directly on the stack (or inline inside an object on the heap). Reference types store a pointer to heap-allocated memory.

▸Value types: int, double, bool, struct, enum — copied on assignment. Changes to a copy don't affect the original.
▸Reference types: class, interface, delegate, string, array — assignment copies the reference, not the data. Both variables point to the same object.
▸Structs are value types — passed by value by default; use ref/out/in to pass by reference.
⚠️Why it matters: Reference-type aliasing is a common source of subtle mutation bugs. Choosing struct vs class directly affects GC pressure, memory layout, and performance in tight loops.
Q2 Explain boxing and unboxing. What are the performance implications?
✔ Answer

Boxing converts a value type to object (heap allocation). Unboxing extracts the value type back from object with a runtime type-check.

int x = 42; object boxed = x; // Boxing — new heap allocation int unboxed = (int)boxed; // Unboxing — type-check + copy
▸Each boxing creates a new heap object → increased GC pressure.
▸Avoid in hot paths by using generics (List<int> vs ArrayList) or Span<T>.
▸Common hidden boxing: using a value type as an interface, string formatting with object params pre-C#10.
Q3 What is the difference between const and readonly?
✔ Answer
▸const: Compile-time constant. Must be a primitive/string literal. Inlined at compile time into all consumers. Implicitly static.
▸readonly: Runtime constant. Can be any type. Set only in declaration or constructor. Instance field.
▸static readonly: One shared instance, set once at class initialization. Use for complex objects (e.g., static readonly ImmutableList<string>).
⚠️Pitfall: Changing a public const in a library requires recompilation of ALL consumers (value is baked in). static readonly avoids binary compatibility issues.
Types & Operators
Q4 What are nullable value types and how do they work internally?
✔ Answer

int? is syntactic sugar for Nullable<int> — a struct containing a bool HasValue and a T Value field.

int? x = null; if (x.HasValue) Console.WriteLine(x.Value); int safe = x ?? 0; // null-coalescing fallback
▸Nullable reference types (C# 8+): compiler-level feature only — no runtime change. Enables static flow analysis to warn about possible null dereferences.
▸Enable with #nullable enable or in .csproj with <Nullable>enable</Nullable>.
Q5 Explain the null-coalescing (??) and null-conditional (?.) operators.
✔ Answer
string name = user?.Name ?? "Guest"; // safe nav + fallback user?.Orders?.ForEach(o => Process(o)); // chained null-conditional count ??= 0; // null-coalescing assignment (C# 8)
▸?. short-circuits the entire expression to null if the left side is null — prevents NullReferenceException.
▸?? returns the right-hand value when the left side is null.
▸??= assigns the right-hand value only if the variable is currently null — useful for lazy initialization.
Q6 What is the difference between == and .Equals() in C#?
✔ Answer
▸== for value types: compares values. For reference types: compares references (memory address) unless overloaded.
▸.Equals() is a virtual method — can be overridden for value semantics (e.g., string, DateTime).
▸string special case: overloads == to compare content, so "abc" == "abc" is always true.
▸Object.ReferenceEquals(a, b) always checks reference identity regardless of any overloads.
Functions & Classes
Q7 What is the difference between abstract class and interface in C#?
✔ Answer
▸Abstract class: can have state (fields), constructors, concrete methods, access modifiers. Single inheritance only.
▸Interface: historically only contracts; since C# 8 can have default method implementations. Multiple inheritance supported.
▸Use abstract class when classes share implementation or state (IS-A relationship).
▸Use interface for defining capabilities across unrelated types (CAN-DO relationship, e.g., IDisposable, IComparable).
Q8 What are extension methods and when should you use them?
✔ Answer

Extension methods add methods to existing types without modifying or subclassing them. Defined as static methods in a static class with this on the first parameter.

public static string Truncate(this string s, int max) => s.Length <= max ? s : s[..max] + "...";
▸Good use: utilities on sealed types (string, List<T>), fluent builder APIs, and LINQ-style chaining.
▸Overuse pollutes IntelliSense. Keep extension methods close to the types they extend and in focused namespaces.
Q9 Explain method overloading vs. overriding.
✔ Answer
▸Overloading: same method name, different parameters. Resolved at compile time (static dispatch). No polymorphism.
▸Overriding: subclass redefines a virtual/abstract method. Resolved at runtime (dynamic dispatch via vtable). True polymorphism.
// virtual + override = runtime polymorphism public virtual string GetLabel() => "Base"; public override string GetLabel() => "Derived"; // new = HIDING (not polymorphism — avoid) public new string GetLabel() => "Hidden";

ASP.NET Core MVC
Q10 Explain the ASP.NET Core request pipeline and middleware.
✔ Answer

The pipeline is a chain of middleware components. Each can inspect/modify the request, pass it to the next component, and process the response on the way back.

app.UseExceptionHandler(); // outermost — catches everything app.UseAuthentication(); // must come before Authorization app.UseAuthorization(); app.UseResponseCaching(); app.MapControllers(); // terminal — handles the request
▸Use() passes to next. Run() is terminal (no next call). Map() branches on path prefix.
▸Order is critical: authentication must precede authorization. Exception handler must be outermost to catch errors from all downstream middleware.
Q11 What is the difference between IActionResult and ActionResult<T>?
✔ Answer
▸IActionResult: non-generic, can return any HTTP result type.
▸ActionResult<T>: generic wrapper — return T directly (auto-wrapped in 200 OK) OR any IActionResult for error cases.
▸Enables Swagger/OpenAPI to automatically infer the success response schema.
public ActionResult<UserDto> GetUser(int id) => user is null ? NotFound() : user; // implicit cast to 200 OK
Q12 How does model binding work in ASP.NET Core?
✔ Answer

Model binding maps HTTP request data to action parameters automatically. Sources are tried in a defined order unless explicitly specified.

▸[FromRoute] — URL path segments (/orders/{id}).
▸[FromQuery] — query string (?page=2&size=10).
▸[FromBody] — deserializes JSON/XML body. Only one per action.
▸[FromHeader] — reads from HTTP headers.
▸Custom model binders implement IModelBinder for multi-source or complex scenarios.
Q13 What are Action Filters in ASP.NET Core and what are the filter types?
✔ Answer

Filters inject code at specific stages of the MVC pipeline, implementing cross-cutting concerns without polluting action methods.

▸Authorization filters — run first. Short-circuit if unauthorized. Implement IAuthorizationFilter.
▸Resource filters — run after auth, before model binding. Good for caching at the filter level.
▸Action filters — before/after action execution. Common for validation, logging.
▸Exception filters — handle unhandled exceptions from actions.
▸Result filters — before/after the IActionResult executes (response formatting).
LINQ & Collections
Q14 What is the difference between IEnumerable<T> and IQueryable<T>?
✔ Answer
▸IEnumerable<T>: in-memory LINQ. Data is loaded first; all operations run as C# delegates.
▸IQueryable<T>: builds an expression tree, translated to SQL by EF Core and executed on the database. Only necessary data is fetched.
// BAD: loads ALL orders, filters in-memory var q = ctx.Orders.AsEnumerable().Where(o => o.Total > 100); // GOOD: WHERE clause goes to SQL var q = ctx.Orders.Where(o => o.Total > 100);
⚠️Calling .ToList() or .AsEnumerable() too early converts IQueryable → IEnumerable. All remaining LINQ runs in-memory after loading every row.
Q15 Explain deferred execution in LINQ.
✔ Answer

LINQ queries are not executed when defined — they are executed when enumerated (foreach, ToList(), Count(), First(), etc.).

var query = list.Where(x => x.Age > 18); // Not executed yet list.Add(new Person { Age = 25 }); // This person IS included below foreach (var p in query) { } // Executes NOW against modified list
▸Use .ToList() to materialize immediately when you need a stable snapshot.
▸Multiple enumeration of the same IEnumerable query executes it multiple times — ToList() once and reuse.
Q16 What is the difference between Select and SelectMany?
✔ Answer
▸Select: projects each element to a new form — 1:1 mapping. Result is IEnumerable<IEnumerable<T>> for nested collections.
▸SelectMany: flattens one level of nesting — 1:many mapping. Result is a single IEnumerable<T>.
// Select → nested: IEnumerable<IEnumerable<OrderItem>> var nested = orders.Select(o => o.Items); // SelectMany → flat: IEnumerable<OrderItem> var flat = orders.SelectMany(o => o.Items);
Dependency Injection
Q17 Explain the three DI lifetime scopes in ASP.NET Core.
✔ Answer
▸Transient (AddTransient): new instance on every injection. Best for lightweight, stateless services.
▸Scoped (AddScoped): one instance per HTTP request (per DI scope). Best for DbContext, unit-of-work, repositories.
▸Singleton (AddSingleton): one instance for the entire app lifetime. Must be thread-safe.
⚠️Captive dependency: injecting a Scoped service into a Singleton is a bug — the Scoped service lives too long and shares mutable state across requests. ASP.NET Core's DI validates this in Development mode.
Q18 What is the Service Locator anti-pattern and why should it be avoided?
✔ Answer

Service Locator uses a global registry (IServiceProvider) to resolve dependencies at runtime inside classes, hiding them from the constructor.

▸Problem 1: Hidden dependencies — not visible in the constructor, making the class impossible to test in isolation.
▸Problem 2: Violates Dependency Inversion Principle — high-level module depends on the container.
▸Problem 3: Runtime errors instead of compile-time errors when a service is missing.
▸Correct approach: constructor injection always. Use IServiceProvider only in factories, middleware bootstrapping, or truly dynamic scenarios.

Entity Framework Core
Q19 Explain the difference between eager, lazy, and explicit loading in EF Core.
✔ Answer
▸Eager loading: Include() — loads related data in the same SQL query via JOIN. Best for known, required navigations.
▸Lazy loading: navigation loaded on first access via proxy. Requires UseLazyLoadingProxies(). High risk of N+1 queries.
▸Explicit loading: context.Entry(order).Collection(o => o.Items).LoadAsync() — manual, on demand. Predictable but verbose.
// Eager loading — one SQL JOIN query var orders = ctx.Orders .Include(o => o.Customer) .Include(o => o.Items) .ToListAsync();
Q20 What is the N+1 query problem and how do you fix it?
✔ Answer

N+1 occurs when fetching N records triggers 1 query for the list plus N separate queries for each related entity.

// N+1: 1 query for orders + N queries for Customer var orders = ctx.Orders.ToList(); orders.ForEach(o => Console.Write(o.Customer.Name)); // lazy load per order! // Fix: eager load with Include var orders = ctx.Orders.Include(o => o.Customer).ToList();
▸Also fix with projection: Select(o => new { o.Id, CustomerName = o.Customer.Name }) — fetches only what you need.
▸Use AsSplitQuery() for multiple collection includes to avoid Cartesian explosion.
Q21 What are owned entities in EF Core and when do you use them?
✔ Answer

Owned entities belong to another entity and have no independent identity. They map to the owner's table by default (no separate primary key).

modelBuilder.Entity<Order>().OwnsOne(o => o.ShippingAddress); // ShippingAddress columns are embedded in the Orders table
▸Perfect for DDD Value Objects: Address, Money, DateRange — they have no separate lifecycle.
▸Owned entities cannot be queried independently (no DbSet<Address>).
▸Use OwnsMany for collections of value objects stored in a separate table.
Asynchronous Programming
Q22 What is the difference between Task and ValueTask?
✔ Answer
▸Task: a reference type — always allocates on the heap, even for already-completed operations.
▸ValueTask: a value type — avoids heap allocation when the result is available synchronously (cache hit, fast path).
▸Use ValueTask for high-frequency APIs where results are often synchronous (e.g., IAsyncEnumerable, cache reads).
⚠️Important: Never await a ValueTask more than once, and never store it in a field — unlike Task, it is not safe to reuse.
Q23 What is async void and why is it dangerous?
✔ Answer

async void cannot be awaited. Exceptions thrown inside it propagate to the SynchronizationContext and crash the process.

// DANGEROUS — exception is unobservable by caller async void LoadData() { throw new Exception("Crash"); } // CORRECT — return Task so callers can await and handle async Task LoadDataAsync() { throw new Exception("Caught"); }
▸Only valid use: event handlers (required by EventHandler delegate signature).
▸In all other cases, return async Task. Use Roslyn analyzer AsyncFixer to catch async void usage automatically.
Q24 What is ConfigureAwait(false) and when should you use it?
✔ Answer

By default, await resumes on the captured SynchronizationContext (UI thread / ASP.NET request context). ConfigureAwait(false) skips that restore step.

▸Use in library/infrastructure code to avoid deadlocks and reduce context-switching overhead.
▸Do NOT use in UI code or anywhere you need to update the UI after await — you must be back on the UI thread.
▸ASP.NET Core has no SynchronizationContext, so ConfigureAwait(false) has negligible impact there — but it's still best practice for portable library code.
Q25 How do you handle cancellation in async methods?
✔ Answer
public async Task DoWorkAsync(CancellationToken ct = default) { ct.ThrowIfCancellationRequested(); // cooperative check await _repo.FetchAsync(ct); // propagate to IO await Task.Delay(1000, ct); // cancellable wait }
▸Always accept CancellationToken in public async APIs. Propagate it to every async call.
▸Link tokens: CancellationTokenSource.CreateLinkedTokenSource(ct1, ct2) for composite cancellation (request timeout + user cancel).
▸ASP.NET Core automatically passes the HTTP request's CancellationToken as HttpContext.RequestAborted.
Testing (xUnit / NUnit)
Q26 What is the difference between unit, integration, and end-to-end tests?
✔ Answer
▸Unit tests: one class/method in isolation. All dependencies mocked. Fast, deterministic. Run on every commit.
▸Integration tests: multiple real components together (controller + service + real DB). Slower. Cover actual interactions and wiring.
▸E2E tests: entire system via its public interface (browser, HTTP). Slowest. Highest confidence. Run in CI.
▸Test Pyramid: many unit → fewer integration → minimal E2E. Inverting this ("ice cream cone") leads to slow, flaky test suites.
Q27 What is the AAA pattern in testing?
✔ Answer
// Arrange — set up dependencies and input var repo = new Mock<IOrderRepository>(); repo.Setup(r => r.GetByIdAsync(1, default)).ReturnsAsync(order); var svc = new OrderService(repo.Object); // Act — execute the unit under test var result = await svc.GetOrderAsync(1); // Assert — verify outcome Assert.NotNull(result); Assert.Equal("Pending", result.Status);
▸Keep each test focused on one behavior. One Act, multiple Asserts on related properties is fine.
Q28 What is mocking and when should you use it?
✔ Answer

Mocking replaces real dependencies with controlled fakes that return predefined values or verify call interactions.

var mock = new Mock<IOrderRepository>(); mock.Setup(r => r.GetByIdAsync(1, default)).ReturnsAsync(order); mock.Verify(r => r.SaveAsync(It.IsAny<Order>(), default), Times.Once);
▸Use Moq or NSubstitute to mock interfaces in unit tests.
▸Don't mock types you don't own (e.g., HttpClient directly — wrap it behind an interface or use IHttpClientFactory).
▸Over-mocking leads to brittle tests that break on implementation changes. Test behavior, not implementation details.
Clean Architecture
Q29 Explain the layers in Clean Architecture and their responsibilities.
✔ Answer
▸Domain: Entities, Value Objects, Domain Events, Aggregates. Zero external dependencies. Pure business rules.
▸Application: Use Cases (Commands/Queries via CQRS), DTOs, interfaces (IOrderRepository). Depends only on Domain.
▸Infrastructure: EF Core, file system, external APIs, email. Implements Application interfaces.
▸Presentation: Controllers, Minimal API, gRPC, CLI. Calls Application use cases. No business logic.
▸Dependency Rule: source code dependencies always point inward. Inner layers know nothing about outer layers.
Q30 What is the Dependency Rule and why is it the core of Clean Architecture?
✔ Answer

The Dependency Rule states that nothing in an inner layer can depend on anything in an outer layer. All dependencies point inward toward the Domain.

This is enforced via Dependency Inversion: Application defines IOrderRepository; Infrastructure provides EfOrderRepository : IOrderRepository. DI wires them at startup.

▸Benefit: Core business logic has zero framework/database dependencies — it is 100% unit-testable without spinning up a DB.
▸Practical check: if your Domain project references Microsoft.EntityFrameworkCore, you've violated the rule.
C# Design Patterns
Q31 Explain the Repository pattern and its benefits and pitfalls.
✔ Answer

Repository abstracts data access behind an interface, decoupling business logic from the persistence technology.

public interface IOrderRepository { Task<Order?> GetByIdAsync(int id, CancellationToken ct); Task AddAsync(Order order, CancellationToken ct); Task SaveChangesAsync(CancellationToken ct); }
▸Benefits: Testable (mock the interface), swappable storage (replace EF with Dapper), consistent querying surface.
▸Anti-pattern: Generic Repository<T> that exposes IQueryable<T> — leaks EF abstractions and defeats the purpose.
Q32 What is the CQRS pattern?
✔ Answer

CQRS (Command Query Responsibility Segregation) separates read and write operations into distinct models — different handlers, possibly different data stores.

▸Commands: mutate state, return void or a minimal result (ID). E.g., CreateOrderCommand.
▸Queries: read state, never mutate. E.g., GetOrderByIdQuery.
▸MediatR is the standard .NET library — IRequest<T> + IRequestHandler<TRequest, TResponse>.
▸Benefit: Read models use fast, raw SQL (Dapper) while writes use full EF with domain logic. Each side scales independently.
Q33 Explain the Decorator pattern with a real-world .NET example.
✔ Answer

Decorator wraps an object to add behavior transparently, without modifying the original class — a clean application of the Open/Closed Principle.

public class CachedOrderRepository : IOrderRepository { private readonly IOrderRepository _inner; private readonly IMemoryCache _cache; public async Task<Order?> GetByIdAsync(int id, CancellationToken ct) => await _cache.GetOrCreateAsync($"order:{id}", _ => _inner.GetByIdAsync(id, ct)); }
▸Register with Scrutor: services.Decorate<IOrderRepository, CachedOrderRepository>().
▸Stack multiple decorators: caching → logging → retry — all transparently composable.
Q34 What is the difference between Factory Method and Abstract Factory patterns?
✔ Answer
▸Factory Method: defines an interface for creating one product. Subclasses decide the concrete class. Extends via inheritance.
▸Abstract Factory: creates families of related products without specifying concrete classes. Groups multiple factory methods. Extends via composition.
▸Example Factory Method: INotificationFactory.Create() → either EmailNotification or SmsNotification.
▸Example Abstract Factory: IUIFactory.CreateButton() + CreateDialog() + CreateInput() — consistent UI kit per theme.

Microservices Architecture
Q35 What are the key principles of microservices architecture?
✔ Answer
▸Single Responsibility: each service owns exactly one business capability (Order Service, Payment Service, etc.).
▸Autonomous: independently deployable, with its own database (database-per-service). No shared schemas.
▸Resilient: failures in one service do not cascade. Circuit breakers, retries, and timeouts are mandatory.
▸Decentralized: each team owns their service end-to-end (code → deploy → operate).
▸Communication: synchronous via REST/gRPC, or asynchronous via messaging (Service Bus, Kafka, RabbitMQ).
Q36 What is the API Gateway pattern?
✔ Answer

An API Gateway is the single entry point for all clients. It handles cross-cutting concerns and routes requests to downstream microservices.

▸Responsibilities: authentication, rate limiting, SSL termination, request routing, response aggregation, load balancing.
▸.NET options: YARP (Microsoft's reverse proxy), Ocelot, Azure API Management.
▸BFF (Backend for Frontend): a variant where each client type (mobile, web, partner) has its own tailored gateway.
Q37 How do you handle distributed transactions in microservices?
✔ Answer

2-phase commit (2PC) is avoided — it creates tight coupling and availability problems. Use the Saga pattern instead.

▸Saga — Choreography: services publish events and react to each other's events. Simple but hard to trace/debug.
▸Saga — Orchestration: a central saga coordinator directs each step and handles failures. More complex but auditable. Use MassTransit Sagas in .NET.
▸Always design compensating transactions (rollback steps) for each step that can fail.
▸Embrace eventual consistency — data will be consistent, just not immediately.
Q38 What patterns do you use to make microservices resilient?
✔ Answer
▸Circuit Breaker (Polly): stop calling a failing service. After N failures, open the circuit for a cool-down period.
▸Retry with exponential backoff + jitter: retry transient failures, delay longer between each attempt, add randomness to avoid thundering herd.
▸Timeout: never wait indefinitely — set explicit timeouts on all downstream calls.
▸Bulkhead: limit concurrent calls to a service so failures don't exhaust shared thread pools.
services.AddHttpClient<IOrderClient>() .AddPolicyHandler(GetRetryPolicy()) .AddPolicyHandler(GetCircuitBreakerPolicy());
Azure Integration
Q39 What is the difference between Azure Functions and Azure App Service?
✔ Answer
▸Azure Functions: serverless, event-driven. Pay per execution. Scales to zero. Cold-start latency. Best for discrete triggered tasks (webhooks, timers, queue processing).
▸App Service: always-on PaaS. Predictable cost and latency. Min-instance control. Best for long-running APIs and web apps with consistent traffic.
▸Azure Container Apps: serverless containers with KEDA-based autoscaling. Good middle ground for microservices requiring container control without cold-start overhead.
Q40 What is Azure Service Bus and when would you use it over a direct HTTP call?
✔ Answer

Azure Service Bus is an enterprise message broker supporting queues (point-to-point) and topics/subscriptions (publish/subscribe).

▸Use when: decoupling microservices, guaranteed delivery, ordering, dead-letter handling, fan-out to multiple consumers.
▸Queues: one sender, one receiver. Topics: one sender, multiple filtered subscribers.
▸Prefer HTTP when: synchronous response is required (request/response pattern), low latency is critical, simple point-to-point.
▸In .NET, use MassTransit or the Azure.Messaging.ServiceBus SDK for clean, testable integration.
Q41 How do you integrate Azure Key Vault in a .NET application?
✔ Answer
builder.Configuration.AddAzureKeyVault( new Uri($"https://{vaultName}.vault.azure.net/"), new DefaultAzureCredential()); // Managed Identity — no secrets in code! // Access secrets transparently via IConfiguration var connStr = config["ConnectionStrings--Default"];
▸DefaultAzureCredential tries Managed Identity, environment variables, VS dev credentials — no passwords in config.
▸Secret rotation is transparent in App Service with Key Vault references.
▸Use separate vaults per environment (dev/staging/prod) with environment-specific access policies.
CI/CD Pipelines
Q42 What is the difference between Continuous Integration, Delivery, and Deployment?
✔ Answer
▸CI (Continuous Integration): every push triggers an automated build + full test suite. Goal: catch integration bugs early.
▸Continuous Delivery: every passing build is auto-released to staging — always deployable. Manual gate before production.
▸Continuous Deployment: fully automated end-to-end — every passing build goes to production without human approval.
▸In Azure DevOps: CI = Build Pipeline. CD = Release Pipeline with environment gates and approvals.
Q43 What is blue-green deployment and what problem does it solve?
✔ Answer

Blue-green maintains two identical production environments (blue = live, green = new version). Deploy to green, test it, then switch traffic instantly.

▸Zero-downtime deployments: traffic switch is atomic at the load balancer/DNS level.
▸Instant rollback: flip traffic back to blue if something goes wrong — no re-deploy needed.
▸Azure implementation: Deployment Slots in App Service. Use Swap Slots to promote green → blue.
⚠️Challenge: Database migrations must be backward-compatible with both versions simultaneously during the transition window.
Performance Tuning
Q44 How do you use BenchmarkDotNet to measure performance?
✔ Answer
[MemoryDiagnoser] [SimpleJob(RuntimeMoniker.Net80)] public class StringBenchmarks { [Benchmark(Baseline = true)] public string Concatenation() => "Hello" + " " + "World"; [Benchmark] public string StringBuilder() { var sb = new System.Text.StringBuilder(); return sb.Append("Hello").Append(" ").Append("World").ToString(); } }
▸Always run in Release mode: dotnet run -c Release.
▸[MemoryDiagnoser] reports allocations per operation — critical for identifying GC pressure.
▸Set Baseline = true on one method to get ratio comparisons in the results table.
Q45 What is the difference between Span<T> and Memory<T>?
✔ Answer
▸Span<T>: a ref struct. Stack-only — cannot be stored on the heap, used in async methods, or boxed. Extremely fast. Works with arrays, stack memory, and unmanaged memory.
▸Memory<T>: a regular struct. Can be stored on the heap and used across await boundaries.
// Span — zero allocation string slice (synchronous) ReadOnlySpan<char> slice = input.AsSpan(0, 10); // Memory — async compatible slice ReadOnlyMemory<byte> mem = buffer.AsMemory(0, 256); await stream.WriteAsync(mem, ct);
Q46 How does the .NET garbage collector work?
✔ Answer

The .NET GC is a generational, tracing collector with three generations:

▸Gen 0: newly allocated objects. Collected very frequently. Usually milliseconds.
▸Gen 1: objects that survived Gen 0. Buffer between short and long-lived objects.
▸Gen 2: long-lived objects (singletons, caches). Collected rarely but expensively. Full GC.
▸LOH (Large Object Heap): objects ≥ 85 KB. Always Gen 2. Rarely compacted — can cause fragmentation.
▸Tuning: use ArrayPool<T>/ObjectPool<T> to reuse large objects, enable Server GC in web apps via gcServer=true.
Advanced C# Features
Q47 What are records in C# and how do they differ from classes?
✔ Answer
▸Records are reference types with value-based equality — equality compares property values, not references.
▸Immutable by default with init-only properties. Compiler generates Equals, GetHashCode, ToString, and Deconstruct.
public record OrderDto(int Id, string Status); var original = new OrderDto(1, "Pending"); var updated = original with { Status = "Shipped" }; // non-destructive mutation Console.WriteLine(original == updated); // false — value equality
▸record struct (C# 10): value type record. Best for small immutable value objects (coordinates, money amounts).
Q48 What is pattern matching in C# and what forms does it take?
✔ Answer

Pattern matching allows branching on the shape and content of data, far beyond simple type checks.

string Describe(object o) => o switch { int n when n < 0 => "negative int", int n => $"positive {n}", string { Length: 0 } => "empty string", not null => "something else", null => "null" };
▸Patterns: type, declaration, constant, relational, logical (and/or/not), property, positional, list (C# 11).
▸Switch expressions are exhaustive — the compiler warns if a case is unreachable or missing.
Q49 What are Source Generators and what problems do they solve?
✔ Answer

Source Generators run at compile time and produce C# code added to the compilation — replacing runtime reflection.

▸Real-world examples: System.Text.Json serialization ([JsonSerializable]), [GeneratedRegex], gRPC stubs, DI registrations.
[GeneratedRegex(@"\d{4}-\d{2}-\d{2}")] private static partial Regex DatePattern(); // compiled regex, zero reflection
▸Benefits: zero runtime overhead, AOT (Native AOT) compatible, generated code is visible in IDE.
▸Implement IIncrementalGenerator (preferred over ISourceGenerator) for IDE performance.
Q50 What is unsafe code in C# and when is it appropriate?
✔ Answer

unsafe allows direct pointer manipulation, bypassing the CLR's type safety and garbage collector tracking.

unsafe void XorBuffer(byte* src, byte* dst, int len) { for (int i = 0; i < len; i++) dst[i] = (byte)(src[i] ^ 0xFF); }
